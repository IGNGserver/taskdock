01数据模型

一个任务，
只有一个事实。

目录决定任务放在哪里，日期与时间点决定什么时候关注它，流程记录它走到哪个阶段，步骤拆解它具体怎么做。四个维度彼此独立，引用的始终是同一个任务——在任何一处改变状态，所有视图同时更新。

02日期与时间点

什么时候做，
交给时间轴。

把任务安排到某一天，或者挂在一个还没有确定日期的事件上。安排只是一条引用：同一个任务可以同时出现在好几处，完成一次，处处完成。

拖到时间轴上，或点选后再点目标列：
试试把任务拖到另一天：它不会被复制，只是多了一处安排。

安排不是复制

加入日程只增加一条安排关系，标题、状态和笔记仍然只存在于任务本身。

顺延可以撤销

把某一天仍未完成的安排批量顺延到次日，自动跳过已完成或已归档的任务，随时可以撤销。

事件到达不改任务

「上线前」「额度重置后」这样的事件到达，只改变事件本身；任务是否完成，仍然由你决定。

03离线优先

断网的时候，
工作不会停。

界面先读本地数据，不等网络。每次修改和它的待同步记录在同一个本地事务里写入；恢复连接后按顺序推送，再拉取其他设备的变化。

  • 先读本地。浏览器使用 IndexedDB，Android 使用 Room，打开就能用。
  • 按顺序重放。修改先进入待同步队列，联网后逐条推送；同一条修改重试不会重复写入。
  • 冲突不静默覆盖。版本对不上时，同时保留你的修改和服务器快照，由你决定。
  • 高风险操作不冒险。整棵目录删除、批量顺延这类操作，离线时直接拒绝。
  • 实时但克制。WebSocket 只推送“需要同步”的信号，不携带任务内容。

04自托管

数据放在你自己的
服务器上。

TaskDock 以 Docker 镜像发布在 GitHub Container Registry。服务器上不需要源码，也不需要 Node.js：准备好 compose.yaml 和 .env，拉取镜像、执行迁移、启动，家里的 NAS 也能跑。 

# 在空目录中准备 compose.yaml 与 .env.example
$ cp .env.example .env
# 生成随机密钥，填写 .env 里的密码与令牌
$ openssl rand -base64 48
$ export APP_VERSION=2.0.0-rc.37
$ docker compose pull
$ docker compose --profile operations run --rm migrate
$ docker compose up -d
# 默认访问 http://服务器地址:48731
# 在 .env 中填写 OWNER_USERNAME 与 OWNER_PASSWORD
$ docker compose --profile operations run --rm bootstrap
# 初始化成功后：从 .env 删除 OWNER_PASSWORD，
# 并删除或轮换 BOOTSTRAP_TOKEN
# 先备份数据库，再修改版本号
$ export APP_VERSION=<新版本号>
$ docker compose pull
$ docker compose --profile operations run --rm migrate
$ docker compose up -d
# 出现问题时改回上一个版本号，并按备份恢复文档处理数据库

更新部署说明
05.4

按操作恢复归档

归档文件夹会逐项归档整棵子树；恢复时只恢复这一次操作归档的内容，不会误恢复更早归档的任务。

归档 → 恢复同一次操作
05.5

不变的任务编号

新任务统一使用 TASK-N 全局编号，编号创建后不再改变，在笔记和提交信息里引用都不会失效。

fix: 回滚脚本TASK-214
05.6

跟随系统深浅色

网页端读取系统配色偏好，Android 跟随系统主题。主题属于设备本身，不会同步到其他设备。
