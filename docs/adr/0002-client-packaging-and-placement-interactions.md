# ADR 0002：V1 客户端打包与安排交互边界

## 状态

已接受，适用于 V1。

## 背景

计划基线列出 Electron Forge 和 dnd-kit，但 V1 的产品正确性要求是：本地 Web 资源安全加载、桌面指针拖拽、键盘等价操作、移动端长按/Bottom Sheet，以及可复现的构建产物。当前仓库需要在这些行为可验证的前提下保持依赖和发行链足够小。

## 决策

1. Electron V1 使用 `electron-builder`：现有配置同时产出 Linux 目录包并保留 Windows NSIS 目标；安全属性、资源打包和导航限制由源码 smoke test 直接断言。Windows 安装和签名仍必须在 Windows runner 或具备 Wine 的环境验收。
2. Web V1 使用原生 HTML5 拖拽完成桌面指针操作。每个可排序列表同时提供上移/下移按钮、明确的菜单动作和可见键盘焦点，因此拖拽不是唯一操作路径。
3. 移动端不依赖触摸拖拽：安排、复制、移动和移除通过长按/Bottom Sheet 与同一 REST mutation 完成；Android 使用 Capacitor 适配器处理返回键、生命周期、网络和安全存储。
4. V1 不为引入 dnd-kit 或 Forge 增加额外行为层。若后续需要跨容器统一拖拽传感器、复杂嵌套拖拽或 Forge 专有发布流程，再单独评估迁移，不改变 Task/Placement 语义。

## 后果

- 自动化门禁可以直接验证当前实现的安全设置、键盘替代和移动端可达入口，但不能把 Linux 构建证明为 Windows 实机安装成功。
- 原生拖拽事件不是移动端正确性的前置条件；所有安排动作都有按钮或菜单等价路径。
- 如果列表达到高容量或需要跨容器拖拽，必须在引入新库前补充性能、可访问性和真实设备验收。
