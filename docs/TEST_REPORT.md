- 内存后端：显式 `E2E_REAL=1` 时，Chromium/移动 Chromium 8/8 通过，Firefox 4/4 通过。
- 临时用户态 PostgreSQL 18：数据库 `devtodo_e2e_20260907` 上，Chromium/移动 Chromium 8/8 通过；覆盖初始化/登录、今日任务创建、第二浏览器 context 读取同一任务、移动导航可见性、核心 smoke 与 axe。删除前计数为 `users=1`、`tasks=2`、`placements=2`，随后已删除临时库。
- 独立备份恢复：`MISC-1` 的恢复后备注为 `version=2`，内容包含“备份恢复验收”；`pg_dump -Fc` / `pg_restore` 后计数为 `users=1`、`tasks=3`、`placements=3`、`notes=3`、`schema_migrations=4`。这证明 PostgreSQL dump/restore 业务不变量，不等于 Docker Compose build/up、重启和卷恢复通过。
- release gate 数据库清理：`devtodo_release_20260908_205701_17223` 结束后为 `users=0`、`tasks=0`、`time_points=0`、`placements=0`、`notes=0`、`schema_migrations=4`；浏览器 E2E 唯一测试 Owner 已显式删除，fixture cleanup 为 PASS。
- 上述证据证明基础真实 API 与跨 context 数据读取链路，不等于 Docker Compose/生产部署、长期离线、冲突、响应丢失恢复或完整双客户端同步验收。

## 已覆盖的领域与协议

- Task 状态完成/重开、`completedAt`、Event 到达/归档独立性。
- Project 与全局 MISC 约束、稳定引用 ID、rank 排序、日期跨月、同一 Task 多 Placement。
- Placement add/copy/move/remove/reorder、rollover/undo。
- HTTP 和 sync mutation 幂等、版本冲突、refresh rotation/replay revoke、失败 push 的保留与指数退避。
- Owner 范围查询、稳定 keyset 列表分页、无效游标、同步 cursor 原子推进与 cursor 过期重同步。
- Markdown 原始 HTML/XSS 清理、外部链接 scheme 限制和任务引用解析。
- 离线本地写入与 outbox 同一 IndexedDB 事务、严格 FIFO、创建依赖顺序、服务器 ID remap、pending intent 保护、冲突合并和归档实体恢复后重试。
- 今日快速创建同时产生 Task 和今日 Placement；移动端底栏、FAB 和 Bottom Sheet 代码路径已覆盖静态/核心 smoke 边界。

## 发行与验收限制

当前结果区分“源码/构建/静态安全证据”和“真实数据库、网关、Windows、Android 设备、iOS WebKit、备份恢复、长期双客户端同步及容量证据”。正式部署仍需按 [DEVELOPMENT_PLAN.md](../DEVELOPMENT_PLAN.md) 第 18 节使用独立环境执行；任何失败都应保留 request ID、客户端日志、服务端日志和最小复现条件。当前 `release:gate` 的 `FAIL` 是由未运行环境门禁造成，不代表已证明这些门禁的业务实现通过。
