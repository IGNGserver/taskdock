# TaskDock Material 3 UI 重构说明

> 目标：保留 TaskDock 的离线优先、自托管、同步冲突与开发者任务语义，同时把操作路径收敛到主流 Todo 产品已经验证过的“先捕获、再安排、单击完成、随时重排”模型。

## 1. 产品特色与不能破坏的语义

TaskDock 不是普通的清单应用，而是一个开发者工作台：

- **Task 是唯一任务本体**：标题、状态、优先级、项目归属和备注只存一份。
- **Placement 是安排位置**：同一任务可以出现在多个日期或自定义时间点；安排、移动、再安排都不复制 Task。
- **日期和事件分离**：日期适合 Today/日历，事件适合发布、值班、版本窗口等开发节点；事件到达不等于任务完成。
- **同步可解释**：离线、本地缓存、冲突、拒绝 mutation 和回滚都必须继续可见，不能用装饰性的“假成功”替代真实状态。
- **项目与全局杂项有规则**：项目任务和全局杂项不能靠 UI 任意混用，前端的入口文案必须与服务端约束一致。

因此本轮没有引入强绑定的第三方组件库，也没有迁移 React/Vite。Material 3 作为视觉与交互语言落在现有 CSS/React 结构上，降低迁移风险。

## 2. Material 3 方向

选用 **Material 3 Developer Workbench**：

- 使用 `primary / primary-container / surface-container / outline` 等语义色角色，不再把颜色散落在页面级 CSS 中。
- 用 tonal surface 表达层级，少用厚重阴影和“卡片套卡片”。
- 主要按钮使用 40px 以上触控高度，圆角按钮/芯片和 12–28px 容器圆角遵循 M3 的可扫描性。
- 状态、筛选、优先级使用 chip/segmented control；危险动作保留明确的红色语义。
- 保持列表优先：任务行是主界面，详情是补充，不强迫用户为每个微操作打开详情抽屉。
- 桌面端保留开发者信息密度（引用 ID、项目代号、同步状态），移动端扩大触控目标并减少同时显示的次要操作。

## 3. 主流 Todo 的可借鉴操作逻辑

### 捕获

- 全局快捷入口只要求一个标题，回车立即创建。
- 创建后先进入收集箱/任务库；是否安排到今天由明确的上下文决定，不让系统悄悄替用户移动任务。
- Today 中的行内捕获自动建立“今天”的 Placement，并在界面上说明这一点。

### Today / My Day

- Today 是当日焦点视图，不是任务本体的另一个副本。
- 未完成任务与已完成任务分区；已完成默认折叠，保持注意力在下一步。
- “从任务库加入”是添加 Placement；“安排到明天”是批量创建明天的 Placement，并提供撤销。

### 完成与状态

- 主任务行上直接完成，不需要打开详情。
- TaskDock 还存在 `IN_PROGRESS`，因此紧凑状态控件按 `TODO → IN_PROGRESS → DONE → TODO` 循环；详情页仍可精确编辑。
- 完成是 Task 级语义，所有 Placement 同步显示完成状态。

### 安排与移动

- 任务行把“安排到时间点”作为一等操作，而不是藏在多级菜单里。
- 安排弹层先给“今天 / 明天 / 自定义日期”，再切换到事件；日期和事件不在一个难以扫描的长下拉里混杂。
- 时间视图中的“移动”改变当前 Placement，“再安排/复制到其他时间点”创建同一 Task 的新 Placement；“复制任务”才创建新的 Task。

### 组织与反馈

- 筛选只改变视图，不改变任务状态。
- 拖拽排序和键盘上下移动都调用同一排序契约。
- 所有 mutation 都保留加载中、错误、冲突和撤销反馈；网络失败不能让行看起来已经成功。

## 4. 当前问题与本轮修复

| 当前问题                                           | 风险                                                | 本轮处理                                                         |
| -------------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------- |
| `IN_PROGRESS` 只能显示，紧凑任务行不能进入该状态   | 状态模型与可操作 UI 不一致                          | 状态按钮改为三态循环，并补充纯函数契约测试                       |
| 任务的“安排到时间点”藏在更多菜单                   | 高频操作成本高，用户不知道 Task 与 Placement 的区别 | 行内增加直接安排入口；安排弹层提供日期快捷选项                   |
| 任务库拖拽可开始，但列表没有统一 drop/reorder 目标 | 用户以为拖拽有效，实际可能没有排序结果              | TaskList 接入统一拖拽排序，与上下移动使用同一个 `/tasks/reorder` |
| 任务选择器必须输入搜索词才有内容                   | Today 添加已有任务时缺少可浏览入口                  | 打开时加载未归档任务作为建议，输入后再搜索                       |
| “复制到其他时间点”容易被理解为复制任务             | 误解 Task/Placement 语义                            | 改成“再安排到其他时间点”，并在弹层中明确“不会复制任务本体”       |
| 一级导航把全局杂项放在次级，缺少 Inbox 心智模型    | 捕获后无明确落点                                    | 保留 `/misc` 兼容入口，新增 `/inbox` 收集箱命名与导航入口        |
| 旧 CSS 以页面级颜色和窄小控件为主                  | 视觉层级和移动端触控一致性不足                      | 引入 M3 语义令牌、tonal surface、40px 控件和移动底部导航覆盖     |

## 5. 分阶段落地与验收

1. **基础层**：Material 3 令牌、通用按钮/图标按钮/chip/分段控件、行为纯函数和文档。
2. **核心流**：收集箱、Today、任务库、快速捕获、任务行、安排/重排。
3. **外围流**：项目、日历、事件、归档、设置、详情、移动端 shell 使用统一视觉层。
4. **回归层**：类型检查、构建、单元测试、现有 API/同步回归；真实浏览器、真实移动设备和离线冲突仍单列证据，不把本地构建当成完整产品验收。

验收重点：

- 完成 Task 后，所有 Placement 都显示完成；移除 Placement 不删除 Task。
- “移动”与“再安排”不会产生 Task 副本；“复制任务”才会产生新 Task。
- Today 行内捕获确实进入当天；全局捕获进入收集箱，不悄悄安排日期。
- 离线/冲突/拒绝 mutation 的现有提示与同步机制不被视觉重构吞掉。
